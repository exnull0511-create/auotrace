## 分析で分かったこと

1. **試走タイムなど誰でも見られる情報は、オッズにほぼ織り込まれている。** 人気・試走順位・予測順位・ハンデ別の1着率は市場の確率と±2%以内。試走・偏差・ハンデ・ST・走路・気温・前走比など14項目のモデルも、検証期間（2025〜）で市場と同じ精度（`ai/model.py`）。
2. **3連単は高配当ほど損。** 回収率は200倍未満で70〜79%、1000倍以上で約41%。
3. **勝ち筋の候補: 単勝と3連単のオッズの食い違い**（`ai/pool_gap.py`）。
   - ルール: 3連単の確定オッズから出した1着確率 × 単勝の確定オッズ ＞ 1.2 の単勝を買う。
   - 2018〜2026年: 28,250点・的中3,770（13.3%）・**回収率167%**。年別138〜189%、場別162〜173%、オッズ帯すべて140%以上。
   - 単勝の確定オッズは払戻金と一致することを確認済み（データの誤りではない）。
   - 1点の的中率13%、5レースに1回当たり、最長71連敗、プラスの日は48%。
   - **ただし確定オッズでの計算。** 年々下がっている（2018〜19年 約185% → 2022年以降 約145%）。
4. **締切前オッズは最後に大きく崩れることがある。** 11/20 浜松6R: 締切3分前に単勝2番7.2倍（推奨）→ 確定2.5倍。単勝の票の大半は締切直前の1分に入る（締切1分前でも確定時の1/4程度の票しか無いことがある）。締切3分前の判定では大穴が過大評価されやすい（浜松4R: 3分前4点推奨 → 1分前2点）。

## 決定済みのこと

- データ源は autorace.jp 公式の内部API。過去分は 2018年から（2014年まで遡れるが未取得）。
- 試走タイム等を足した予想モデルは、市場を超えないので主軸にしない。
- 主軸は「単勝と3連単の食い違い」。締切前オッズで検証してから実運用を判断する。
- 自動投票はしない（規約）。候補の提示・LINE通知まで。購入は本人。
- LINE通知は検証が済むまで停止。再開は新しいルールで、ユーザーの了承を得てから。
- 1点の金額は数百円まで（単勝の売上が小さいため）。
- 修正は main に直接 push（ユーザーはスマホでマージできない）。
- GitHub の cron は当てにならないので、オッズ監視は自己起動・見張り係は相互起動で補う（11/20 17:04 から新方式）。

## 未解決の課題

1. **勝ち筋が買える時点で残るか**（最重要）。締切前オッズで判断して、確定オッズの払戻で回収率100%を超えるか。崩れ方（オッズ帯・その時点の票数・乖離の大きさ・場・時間帯）から確定オッズを予測し、その予測値で判断するルールが作れるか。→ 12/9 の自動検証。
2. **11/20 17:04 からの起動方式の変更が効いているか**（見張り係が30分ごとに起動されるか、オッズ監視が途切れず翌朝自動で始まるか）。11/20 17:50 に確認予定。
3. LINE 公式アカウントの無料プランは月200通。推奨が1日10〜25レースなら超える可能性。再開時に「有料プラン（月5,000円・5,000通）」か「通知を絞る（オッズ上限など）」を決める。
4. 締切前オッズの記録は1日数MB。数か月で data ブランチが重くなる。いずれ古い odds_ts を圧縮・間引く必要あり。
5. `backfill.yml` は毎回 `repair`（全期間のカレンダー再取得、数分）を走らせている。過去分が揃ったら頻度を落としてよい。
6. `ai/model.py` の係数の z 値は L-BFGS の近似ヘッセ行列からで当てにならない（参考にしない）。
7. 過去分の取得範囲を 2014〜2017年に広げるかは未決定（古い年は規則・車両が違う可能性）。
